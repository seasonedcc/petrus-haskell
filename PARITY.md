# Parity

Status of every in-scope upstream component against the pins in
[UPSTREAM.md](UPSTREAM.md).

A component is **at parity** only when all of these hold at the current pin:

1. **Tests** — every behavior its upstream tests check is checked by a Haskell
   test (or recorded as enforced by the Haskell types), by the same method:
   where upstream generates inputs (Hypothesis strategies, stateful machines),
   the Haskell test generates them too (Hedgehog or QuickCheck), with the
   same settings, the same explicit examples, and a fixed seed where upstream
   derandomizes. Deterministic enumeration may be added on top, never instead.
2. **Conformance** — everything `upstream/petrus/spec/` (and this repo's
   `spec/`) specifies for it holds.
3. **Interop** — where it has a wire format or protocol, Haskell and Python
   exchange it in both directions with no loss.
4. **Performance** — its committed benchmarks show it at least as fast as the
   pinned Python on equivalent workloads.

Statuses: `not started`, `in progress`, `at parity`, `out of scope` (with the reason; see [SCOPE.md](SCOPE.md)), and `optional` (an extra check that parity does not depend on, with the reason). Evidence links point at
the tests, conformance suites, and benchmark results that justify the status.

Counts of upstream tests and cases, here and in the package ledgers, are
what pytest collects at the pins; `scripts/check-parity` checks every one of
them against [docs/upstream-test-counts.json](docs/upstream-test-counts.json)
and refuses a count it cannot read. The
documents do not state how many Haskell examples a suite runs, since that
number changes with every test added (`scripts/lint-example-counts` rejects
one). `cabal test <package>` prints it, and every CI run prints each
suite's count in its `test` jobs.
