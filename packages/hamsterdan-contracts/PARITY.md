# hamsterdan-contracts parity

What this package ports from `upstream/hamsterdan` (pinned in
[UPSTREAM.md](../../UPSTREAM.md)) and the evidence for each piece. Every
expectation in the corpora was produced by the pinned Python running the
committed generator scripts:

- `upstream/hamsterdan/.venv`
- Python 3.14.6
- pydantic 2.13.4, pydantic-core 2.46.4

The Haskell suite compares bytes.

## Upstream tests

`tests/unit/readiness/test_payloads.py` is the upstream test module for these
contracts. Every test is ported in `test/CodecSpec.hs` under the same name:

| Upstream test | Haskell example |
| --- | --- |
| `test_converter_round_trips_strict_json_workflow_model` | "round trips a strict JSON workflow model" |
| `test_admitted_conversation_is_strict_frozen_and_forbids_provider_fields` | "refuses provider fields and coercion on AdmittedConversation". Frozenness is enforced by the types (immutable records). |
| `test_converter_rejects_coercion_and_extra_fields` (parametrized) | "rejects coercion and extra fields on Authority" (every parameter) |
| `test_closed_workflow_vocabulary_rejects_unknown_actions_state` | "rejects an unknown actions state" |
| `test_converter_rejects_a_different_nominal_result_contract` | "keeps result contracts nominal" |
| `test_readiness_state_tokens_partition_snapshot_fields` | "partitions snapshot fields among the concern tokens". The `Concerns` record also makes the partition a compile-time fact. |
| `test_concern_tokens_project_to_derived_snapshots` (parametrized) | "projects concern tokens to derived snapshots" (both parameters), plus the projection corpus |
| `test_split_tokens_are_strict_and_extra_forbidden` | "refuses coercion and unknown fields on split tokens" |
| `test_converter_round_trips_readiness_snapshot` | "round trips a readiness snapshot" |
| `test_converter_round_trips_immutable_dashboard_request` | "round trips an immutable dashboard request" |

## Not in this package (gaps, by design)

- **`tests/unit/agents/test_protocol.py`**: these tests cover the protocol
  *validators* (`_validate_request`, `_validate_result` and their helpers).
  Plan §6 places the protocol *types* here and result validation in
  `hamsterdan-agents`, where those tests will be ported.
- **Board and dashboard behavior tests** (`tests/unit/readiness/net_v5/test_board.py`,
  `test_dashboard_loop.py`): these test the readiness net, which uses the
  printer and parser from this package. They belong to `hamsterdan-readiness`.
- **The functions of `contracts/readiness.py` beyond the four listed above**:
  the rest of that module is the replacement-workflow (`hamsterdan2`) surface,
  which is out of scope (see [SCOPE.md](../../SCOPE.md)). Its dataclasses are
  ported because V5 tokens embed some of them.

## Known differences

All are listed with their reasons in [DIVERGENCES.md](DIVERGENCES.md). In
short:

- `\N{...}` escapes and the unmodeled literal types are reported as
  `Unsupported`.
- Decode errors name the first failure rather than pydantic's full error
  list. Admission is identical.
