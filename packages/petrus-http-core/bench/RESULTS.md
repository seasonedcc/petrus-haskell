## Wall-clock time, and the earlier figures

These replace a table generated by the old `scripts/bench`, which timed Haskell
in tasty-bench's default CPU time against Python's wall-clock time. On the
round trips CPU time leaves out the time the client waits for the kernel to
deliver the connection and the response, so they read 2.4–2.8× faster than
Python (`roundtrip.get-snapshot` 43.9 µs). Measured the same way as Python they
are 1.6–2.0× faster. The in-memory rows are unchanged.

What each row measures:

- **`roundtrip.*`**: one request on a fresh loopback connection to a server in
  the same process (CPython's `ThreadingHTTPServer` with a
  `BaseHTTPRequestHandler` speaking HTTP/1.0, as both upstream services run
  it; on the Haskell side, this package's server), read to the end, then
  closed with a reset (`SO_LINGER` 0) so `TIME_WAIT` sockets do not pile up.
  Each language uses its own client. The requests are a `GET` of a small JSON
  snapshot, a `POST` with a 1 KiB body, and an `HTTP/2.0` request line that is
  refused.
- **`parse.request-head`**: parsing a browser's request line and headers.
- **`render.send-error`**, **`render.response`**: rendering an error response
  and a JSON response.

## Rerun

From the repository root (`scripts/bench petrus-http-core` runs exactly this block, once;
`scripts/bench-compare petrus-http-core 2` interleaves the two sides and prints the table above).
