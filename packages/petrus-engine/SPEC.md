# petrus-engine: the specification's Engine obligations

This ledger maps each normative statement of the Engine's sections of
`upstream/petrus/spec` (at the pin in [UPSTREAM.md](../../UPSTREAM.md)) to the
Haskell examples that check it. It covers three sections:

- `firing-semantics.md` §Scheduling (lines 145-201);
- `event-history.md` from §Lifecycle scopes through §Activities, not worker
  mechanics (lines 136-261);
- `handler-contract.md` §Petrinet, activity, binding, and execution
  boundaries (lines 190-246): the activity/projection split.

Each statement is paraphrased; the spec's own text is normative. An example is
named as `package: Spec module / example`. Unless another package is named,
the package is `petrus-engine` and the module is in `test/Petrus/Engine/`.
`--match` with the example's text runs it.

Statements that no ported upstream test checked through an Engine got a check
of their own, in `SpecObligationsSpec` ("spec obligations (SPEC.md)"). They are
marked **added**.
