# petrus-agenticus-core parity

This package ports the pure, kernel-independent layers of
`petrus.agenticus`, as pinned at `upstream/petrus` 3f85fc2. Each layer has a
detailed fragment under `parity/`. Every fragment maps every upstream test
function to its Haskell test and lists its gaps.

Each `it` label in the Haskell specs is the upstream test name. Parametrized
tests also carry the pytest parameter id.

## Property-based tests (Hypothesis → QuickCheck)

Two upstream tests in this package use Hypothesis. Both are ported as
QuickCheck properties that use the same strategies and settings. Neither
upstream test has an `@example` or a stateful machine, so the ports have none.

Seed: upstream's `pyproject.toml` sets `addopts = "--randomly-seed=1729"`,
but pytest-randomly reseeds only `random`, factory_boy, Faker, NumPy and its
entry points, never Hypothesis. Neither test sets `derandomize=True`, so
Hypothesis seeds each run from OS entropy and the reference draws fresh
examples on every run. The ports do the same: `hypothesisSettings n` (test
`Petrus.Agenticus.Support`) sets only `maxSuccess = n`, and hspec's per-run
seed drives QuickCheck's generator (a failure prints it, for `--seed`
replay). The ports draw from QuickCheck's generator, not from Hypothesis's,
so the examples are not the ones the reference draws. Only the upstream
tests that set `derandomize=True` have ports with a fixed seed: petrus-impetus
`InstanceReplayPropertiesSpec` and the hamsterdan readiness campaigns.

## Differential corpora

Each corpus is generated by a committed Python script that imports the pinned
reference. Each fragment gives the rerun command.

- `differential/catalog_corpus.{py,json}`: descriptors, resolution snapshots
  and profiles.
- `differential/effect_corpus.{py,json}`: effect payloads, digests and envelopes.
- `differential/hands_corpus.{py,json}`: Hands envelopes and the gateway trace.
- `differential/thread_corpus.{py,json}`: Thread, Episode, Turn and Continuation
  envelopes and transitions, program descriptors and runtime values.
- `differential/custody_corpus.{py,json}`: the stored SQLite schema,
  `KeyContext`, 86 payload cases and 30 sessions of 50 steps each.
  `custody_interop.py` hands sessions between the two implementations in
  both directions.
- `differential/storage_revision.py`: a store whose revision cell was
  tampered with (16 SQL values: text with Unicode digits, underscores and
  the whitespace `int()` skips or not, blobs, reals, infinities), loaded by
  both implementations: the same revision, or `int(row[0])`'s class and
  text.

## Gaps

These come from the fragments:

- Python-only refusals that the Haskell types make unrepresentable:
  - `isinstance` checks on already-typed arguments;
  - non-string-key and tuple payloads;
  - wrong return types from protocol implementations.
- `RuntimeProbeResult` raises a raw `TypeError` from `sorted()` when two
  issues share a code and only one names a component. This is a Python
  crash, and it is not reproduced (`divergences/thread.md`).
- Neither implementation tests a real OS-process crash between the custody
  COMMIT and its cleanup. Both simulate it by abandoning and reopening the
  store.
