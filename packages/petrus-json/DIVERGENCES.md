# petrus-json: divergences from CPython `json`

Intentional differences from CPython 3.14's `json` module, as used by the
pinned Petrus (`upstream/petrus`). Everything not listed here is meant to be
identical; the test suite pins the observable behavior.

| Behavior | CPython 3.14 | petrus-json | Why |
| --- | --- | --- | --- |
| Nesting depth | `json.loads` and `json.dumps` raise `RecursionError` when the C stack runs low: about 116,000 nested containers for `loads` and 104,000 for `dumps` on a 64-bit macOS build (16 MiB thread stacks); other platforms and stack sizes give other figures. The message names the stack (`Stack overflow (used 16352 kB) while decoding a JSON array from a unicode string`). | A fixed bound, `defaultNestingLimit` = 100,000 nested arrays/objects for `surrogateRefusingLoads`, `strictLoads` and `defaultDumps`, configurable per call (`maxNestingDepth`, `nestingLimit`). The message is `maximum nesting depth (100000) exceeded while decoding a JSON array from a unicode string`. Like CPython, the decoder counts every container and the encoder counts only non-empty ones. | CPython's figure is not a contract (it depends on the stack). A fixed bound below every measured figure keeps the behavior deterministic and refuses pathological input instead of growing the Haskell stack without bound. Depths Petrus exercises (the upstream simulation tests use 1,200) are accepted. |
| Lone surrogate escapes (`"\ud800"`) | Accepted by `json.loads`: the `str` holds the surrogate code point (it cannot be encoded as UTF-8; `json.dumps` escapes it again under `ensure_ascii`). | Kept with `loneSurrogates = KeepLoneSurrogates`, as a WTF-8 `Text` (`Petrus.Json.Wtf8`) that compares, orders, counts and re-encodes like the `str` (`dumps` writes `\ud800` under `ensureAscii`, the `str`'s WTF-8 bytes otherwise). Kept by `pythonJsonLoads`, CPython's profile. Refused by `surrogateRefusingLoads` and `strictLoads` (`RefuseLoneSurrogates`) with `JSON strings must contain Unicode scalar values`; the name says what it refuses. | The Petrus formats differ here, so the reader chooses. The event History admits them: the reference writes token data, Activity payloads, identities and failure texts with `json.dumps`, so its JSONL and SQLite stores can hold `"\ud800"`, and `historyLoads` (`Petrus.Impetus.History.Codec`), which both Haskell stores read with, keeps them (interop-tested both ways in `petrus-history-store`). Net definitions and documents refuse them with that exact text (upstream's own), and simulation HTTP refuses them (400) when it re-encodes as UTF-8, so those readers use `surrogateRefusingLoads`; so do the Pi, Codex and custody readers, whose divergences are recorded in their packages. Every reader whose reference is plain `json.loads` uses `pythonJsonLoads` (in Hamsterdan: History, `binding.json`, agent route snapshots, ingress and reconciliation manifests, the e2e tapes and fixtures), and the refusal happens where the reference refuses, when the string is encoded. |
| Parse error messages | `JSONDecodeError` texts with line/column (`Expecting value: line 1 column 1 (char 0)`). | Byte offsets (`Expecting value at byte 0`). | No Petrus wire surface exposes decoder messages; they are diagnostics. The two `ValueError`s that can surface (`Exceeds the limit (4300 digits) …` and the encoder's `Out of range float values …`) match CPython exactly. |
| Refusal texts under hooks | Upstream readers raise their own `ValueError`s from `object_pairs_hook`, `parse_int`, `parse_float` and `parse_constant` (`duplicate JSON member 'a'`, `v3 JSON numbers must use integer token spelling, got 1.5`). Number hooks fire at the token and pairs hooks when the object closes, so a document with two faults is refused for whichever comes first in that order. | `strictLoads` and the `ParseOptions` switches refuse the same documents (the differential checks every profile), with petrus-json's own texts, and a document with two faults may be refused for the other one. | The readers that put the refusal text on a wire build it themselves around petrus-json (`Petrus.Impetus.NetDefinition`, the Pi and DST readers) or use the hook-faithful scanner (`Petrus.Json.Python.Scanner`, whose `jsonDecodeError` gives plain `json.loads`'s exact text) where the reference's exact first fault is observable. |
| Input encodings | `json.loads(bytes)` detects UTF-16 and UTF-32 from the first bytes. | `parseJson` reads UTF-8 only; other bytes are refused as invalid UTF-8. `Petrus.Json.Python.loadsBytes` is `json.loads(bytes)` whole: `detect_encoding`, the `surrogatepass` decode, then the scan. | Every upstream Petrus reader passes `str` (decoded as UTF-8) or UTF-8 bytes; the readers that take other encodings (the DST reader, Hamsterdan's provider and export readers) decode them with `decodeJsonBytes` or call `loadsBytes`. |
| `UnicodeDecodeError` after `surrogatepass` passed a surrogate | The codec reuses one exception object: its attributes (`start`, `end`, `reason`, and so `str()`) name the failure that stopped decoding, but its `args` (and so `repr()`) still name the first error, the surrogate the handler passed. | `loadsBytes`'s `PythonException` carries the failure's arguments, so `str()` matches and `repr()` names the failure. | A `PythonException` is its `args`; nothing that reads `json.loads(bytes)`'s exception reads its `repr` (the Hamsterdan readers compare the class, or print `str()`). `PythonCompatSpec` compares the class and `str()` always and `repr()` wherever CPython's `args` and attributes agree. |
| Python-only `dumps` inputs | `default=`, `cls=`, `skipkeys=`, and non-`str` keys (`int`, `float`, `bool`, `None`, coerced to strings), tuples written as arrays. | Not applicable: `dumps` takes a `Json` value, so a caller converts its own types to `Json` first (what `default=` does in the one upstream call that passes it, `telemetry.py`). | The Haskell types make the inputs CPython has to coerce or refuse unrepresentable. |
| Objects with duplicate keys | A `dict` cannot hold duplicate keys, so `json.dumps` never writes them. | `Object` is a list of members; `dumps` writes them as given, duplicates included. | Keeping members in order is what makes `parseJson` and `dumps` round-trip without a map; every Petrus writer builds objects with distinct keys, and the differential's corpus does too. |
